# Inference-engine patch waiver — PR #4047

## Configs covered

The GB300 Kimi-K3 AgentX entries for DCP8 aggregate, DCP8 disaggregation, and DEP16
disaggregation in `configs/nvidia-master.yaml`, using
`vllm/vllm-openai:nightly-49cb2bbf71cfd36ee5aa33d1e184b1cddff55294`.

## Patches

`benchmarks/multi_node/srt-slurm-recipes/configs/kimik3-optimizations.sh` applies
pinned Python-source patches before serving:

- [vLLM #62069](https://github.com/vllm-project/vllm/pull/62069), head
  `447b27fd1d34acb59780e1c31df2a2727ff17636`: opt-in CuTe context prefill, including
  aligned indptr metadata and compatibility validation. New-token prefill is unchanged.
- [2454c49e76](https://github.com/wzhao18/vllm/commit/2454c49e76b9418f7b5c99c3fcdc492d1a5b28e4):
  use the linear quantization method for quantized routed output projections.
- [f94cf76a74](https://github.com/wzhao18/vllm/commit/f94cf76a74b3e4d9747d5d104cd28f8b48cf103d):
  finalize padded KDA weights during online quantization instead of retaining the
  unquantized checkpoint tensors.
- [92d36311d4](https://github.com/wzhao18/vllm/commit/92d36311d4b8ff08f565a8bc7b35bb74fb6d454c):
  preserve quantization scales in the TP latent-MoE tail path.
- [4244e36bcd](https://github.com/wzhao18/vllm/commit/4244e36bcd75837ae30eaecd62ce3f116ea14a5f):
  exclude unaccepted speculative slots from Mooncake's initial save horizon.

The script also installs the released `tokenspeed-mla==2.0.3`. FlashInfer, NIXL,
Dynamo, and native vLLM extensions are not replaced.

## Why patches are needed

The pinned image does not expose `trtllm_ragged_backend="cute-dsl"`. Its online Kimi
projection paths also need the quantization fixes above to run the selected DEP16
configuration correctly and avoid retaining excess BF16 weights during loading.
The Mooncake fix keeps speculative save metadata within the available token IDs.
The unpatched image can run other configurations; this waiver covers the selected
optimized configurations, not a claim that all Kimi-K3 serving requires patches.

## Removal plan

Replace the image with an official nightly containing these changes and TokenSpeed
MLA 2.0.3, then remove the corresponding patches, setup script, and this waiver.
These are proposed changes, not a claim of upstream approval or merge readiness.
